# Module: Web and UI Role

## Goal

Build a small Angular screen where a user can add project notes, ask a question, and understand which notes support the answer.

## Role boundary

Own `apps/web/`: Angular components, routes, forms, accessibility, and browser-side API integration. Agree on the OpenAPI/API contract before connecting to backend endpoints. Do not put AI credentials or model calls in the browser.

## First screen

Create a project detail screen with four areas:

1. Project name and description.
2. Source form with title, text, and Add Source action.
3. List of existing source titles.
4. Question form with answer, source references, and evidence status.

## Required UI states

- **Empty:** explain how to add the first source note.
- **Loading:** show that the question is being processed and prevent duplicate submits.
- **Answered:** show the answer and source titles returned by the API.
- **Insufficient evidence:** explain that the project notes do not answer the question.
- **Error:** show a short recovery message if the API is unavailable.

## Implementation steps

1. Inspect the existing Angular conventions, routes, forms, and API services.
2. Review the approved feature plan and API contract.
3. Build the project detail screen and source form.
4. Add an API service for project, source, and ask requests.
5. Render answer sources and all required states.
6. Check labels, keyboard navigation, and readable contrast.
7. Add component tests using mocked API responses.
8. Open a pull request linking the plan and contract.

## Codex prompt

> Read `AGENTS.md`, `docs/roles.md`, the approved API contract, and feature plan. Work only in `apps/web/`. Implement the planned project screen using existing Angular patterns. Connect to the agreed API routes, show source titles returned by the backend, and include empty, loading, answered, insufficient-evidence, and error states. Add focused tests with mocked API responses. Keep the design simple and accessible, and do not add model calls or secrets to browser code. Run web checks and explain the UI behavior for human review.

## Verify your work

- A user can add a note and see its title in the source list.
- A user can submit a question with keyboard or button.
- The UI prevents duplicate submissions while waiting.
- The answer shows the returned source titles.
- Insufficient evidence and API errors are clear.
- Inputs have labels and visible validation.
