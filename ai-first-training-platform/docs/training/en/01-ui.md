# 01 · Build the application screen

> Week 3 · 2 hours · Main focus: web and user experience

The team builds this screen from scratch for its chosen record type. The requirement is a form to insert records and a list that shows what was saved. Updating or deleting can be added if there is time.

## Before you start: parts of a screen

- A **screen** is a complete view, such as a page with an article form and list.
- A **component** is a reusable piece of a screen, such as a button, card, or form.
- **React** helps build screens from components. **Vike** connects a site address to the page that appears.

You do not need to memorize these terms. Since this app starts from scratch, ask the assistant to explain which new file it will create for the page and each part of the screen.

## What you will learn

- Find the file that displays a page and the components that draw the screen.
- Use the data agreement with the API instead of making up another format.
- Build a form from scratch with the agreed fields.
- Display the records returned by the API in a list.
- Show loading, success, an empty list, and errors; updating and deleting are optional extensions.
- Ask AI for help and review its changes with another person.

## Files you will create or update

This is a reference structure for your new app; ask AI to confirm the names and create only the files you need.

| Example file | What it should include |
| --- | --- |
| **`apps/web/pages/index/+Page.tsx`** | The initial app page with the form and list. |
| **`apps/web/src/RecordForm.tsx`** | A form to insert the chosen type of record. |
| **`apps/web/src/RecordList.tsx`** | Lists records returned by the API; shows a message if the list is empty. |
| **`apps/web/src/api.ts`** | Requests to insert a record and get the list. |
| **`apps/web/src/RecordPage.test.tsx`** | Tests for the form, list, and main states, if the project includes screen tests. |

Each team's own project may use different paths. Before suggesting a new file, AI should explain why an existing file will not work.

## Step-by-step exercise

1. Sketch a simple screen with a form and a list. Include only the fields the team agreed on.
2. Confirm with API what data the form sends and receives; also agree on the format of the list.
3. Create the page and form with React, one small part at a time. Use `fetch` to send data and request the list.
4. After inserting, refresh the list so it shows the saved record. The list should show a clear message if there are no records yet.
5. Show loading, success, and errors. Check that the screen works with a keyboard and on a small display.
6. If the minimum works and there is time, add update or delete as a new task.

## Prompt for Codex or Claude

> I am responsible for Web/interface on a beginner team. Read README.md, AGENTS.md, the brief, and the criteria. This app is being built from scratch. Before editing, propose the minimum files for a page with an insert form and list; explain what each one will contain and whether any Markdown needs updating. Wait for the team to review the plan. Then create only the screen, connect the form and list to the agreed API, and show loading, success, empty-list, and error states. Do not add update, delete, or other features yet. Explain how to check it and describe each change.

## Result and team review

Someone can insert a record on screen and see it in the list after the page receives the API response. The app keeps the record after the page is refreshed. Updating and deleting can be optional improvements.
