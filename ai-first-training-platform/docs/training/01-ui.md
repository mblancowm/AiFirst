# 01 · Construir la pantalla de la aplicación

> Semana 3 · 2 horas · Foco principal: web y experiencia de uso

El equipo crea esta pantalla desde cero para el tipo de registro que eligió. El requisito es un formulario para insertar registros y una lista que muestre lo que se guardó. Editar o eliminar puede agregarse si queda tiempo.

## Antes de empezar: las piezas de una pantalla

- Una **pantalla** es una vista completa, como una página con un formulario y una lista de artículos.
- Un **componente** es una pieza de esa pantalla que se puede reutilizar, como un botón, una tarjeta o un formulario.
- **React** ayuda a construir pantallas con componentes. **Vike** conecta una dirección del sitio con la página que se muestra.

No necesitas memorizar esos nombres. Como esta app empieza desde cero, pide al asistente que explique qué archivo nuevo creará para la página y para cada parte de la pantalla.

## Qué aprenderás

- Encontrar el archivo que muestra una página y los componentes que dibujan la pantalla.
- Usar el acuerdo de datos con la API, sin inventar otro formato.
- Crear desde cero un formulario con los campos acordados.
- Mostrar en una lista los registros que devuelve la API.
- Mostrar espera, éxito, lista vacía y error; editar y eliminar son extensiones opcionales.
- Pedir ayuda a la IA y revisar sus cambios con otra persona.

## Archivos que crearás o actualizarás

Esta es una estructura de referencia para su app nueva; pidan a la IA que confirme los nombres y creen solo los archivos necesarios.

| Archivo de ejemplo | Qué debe incluir |
| --- | --- |
| **apps/web/pages/index/+Page.tsx** | La página inicial de la app con el formulario y la lista. |
| **apps/web/src/RecordForm.tsx** | Formulario para insertar el tipo de registro elegido. |
| **apps/web/src/RecordList.tsx** | Lista los registros que devuelve la API; muestra un mensaje si está vacía. |
| **apps/web/src/api.ts** | Solicitudes para insertar un registro y pedir la lista. |
| **apps/web/src/RecordPage.test.tsx** | Pruebas del formulario, la lista y sus estados principales, si el proyecto incluye pruebas de pantalla. |

En su propio proyecto, cada equipo puede tener rutas distintas. Antes de proponer un archivo nuevo, la IA debe explicar por qué no sirve uno existente.

## Ejercicio paso a paso

1. Dibujen una pantalla sencilla con un formulario y una lista. Incluyan solo los campos que el equipo acordó.
2. Confirmen con API qué datos envía el formulario y qué respuesta recibirá; acuerden también el formato de la lista.
3. Creen la página y el formulario con React, una parte pequeña a la vez. Usen fetch para enviar datos y pedir la lista.
4. Después de insertar, actualicen la lista para que muestre el registro guardado. La lista debe mostrar un mensaje claro si todavía no hay registros.
5. Muestren espera, éxito y error. Revisen que se pueda usar con teclado y en una pantalla pequeña.
6. Si el mínimo funciona y queda tiempo, agreguen editar o eliminar como una tarea nueva.

## Resultado y revisión del equipo

Una persona puede insertar un registro desde la pantalla y verlo en la lista después de que la página reciba la respuesta de la API. La app conserva el registro al actualizar la página. Editar y eliminar pueden aparecer como mejoras opcionales.
